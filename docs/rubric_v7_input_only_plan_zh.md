## 目标与对照方式

目标是同10题至少8份草案通过来源静态审查，且此前v7暂可保留的8题不出现新的阻断问题。该目标不能保证，也不是执行检查器的准确率。

v7的8/10来自已有v6草稿和逐题反馈的修订。为只考察输入压缩，下一轮沿用每题完全相同的v6草稿和v6反馈、v7系统prompt和序列化约定、模型参数及完整输出结构。不得把它报告为新题一次生成的质量，也不据此预测一万道新题的质量。

## 保留内容

- v7全部约束，系统消息逐字不变。
- 模型直接输出完整五字段、三种判定、coverage、unresolved。停用短字段P/G输出及本地合成判定。
- 原题、完整DDL、接口所有非example属性：参数与返回字段名称、类型、required、默认值、枚举、边界、说明、关系及接口目录。
- 同一对象绑定、完整候选集合、修改前范围、真实事件、未来执行机制和歧义门控要求。
- 此次对照所需的旧稿与审查反馈逐字不变。不再同时改变输入内容、输出结构和修复策略后，把效果统称为压缩。

## 只缩减这些输入

1. 纯示例example属性不再重复发送；原始完整来源仍保存在本地用于查证。
2. 原题同时出现在task与sources.task时，只保留后者，题面正文不删字。
3. 外层JSON去掉格式空白；不对DDL、自然语言规则或旧稿做摘要。
4. 不再按描述长度或关键词决定是否保留返回字段。此前精简脚本的这项启发式不复用。

引用仍由模型按v7格式生成，并对原始完整来源做连续原文校验。压缩后出现引用错误算真实失败，不用本地重写掩盖。

离线输入审计已确认：10题的非example接口内容保留、schema及其他来源不变、旧稿和反馈不变、系统消息和模型参数不变。候选请求只存在文件中，未派发。

## 减少重复调用

- 对这次新输入方案，先做10次调用以取得可比较结果；不能拿8份历史输出充当8次新方案测试。
- 缓存键应绑定题目和来源版本、prompt、模型参数、旧稿/反馈以及输入编码版本，避免错误复用。完全相同请求的已完成响应不再次付费。
- 每题完成结构检查与来源语义审查后固定结果；不因其他题失败而重跑整组。
- 初轮若达到至少8/10，仅对剩余最多2题各做一次完整rubric修复。修复仍用v7约束和完整五字段，发送当前草稿、具体错误和相关原始规则；不采用上一轮不稳定的字段补丁格式。
- 若初轮低于8/10或旧版通过题回退，停止扩展调用并分析原因，不开启第二轮全10题重跑。预算不是必须花完的额度。
- 单并发，大预留请求优先；请求前保守预留，未知用量仍占预算，无自动传输重试。
- 不新增付费自动审查模型。仍由本地检查加当前Codex来源审查评估；若改为自动审查服务，需另估预算。
